# Контракт межпроцессного обмена — ПР №3

Автор: Piray26

## 1. Назначение

Межпроцессный обмен предназначен для получения текущих и исторических значений тегов mini-scada отдельным клиентским процессом.

## 2. Стороны обмена

- Сервер — FastAPI-приложение.
- Клиент — отдельная программа Python.
- Сервер и клиент выполняются в разных процессах и имеют разные PID.

## 3. Выбор механизма обмена

Рассмотрены следующие варианты:

- InMemoryBus — используется внутри одного процесса и не обеспечивает самостоятельный межпроцессный обмен.
- Pipe — подходит для локального обмена, но не соответствует REST-архитектуре проекта.
- TCP-сокет — позволяет реализовать обмен между независимыми процессами и использовать существующий HTTP API.

Выбран TCP-сокет с использованием HTTP/1.1.

## 4. Формат обмена

Клиент отправляет HTTP-запрос, сервер возвращает HTTP-ответ.

Формат полезных данных — JSON.

Граница HTTP-заголовков определяется последовательностью CRLF CRLF. Размер тела сообщения определяется заголовком Content-Length, если он используется.

Клиент должен учитывать возможность получения ответа несколькими операциями чтения.

## 5. Ограничения

Предельный размер HTTP-запроса — 1024 байта (1 КиБ).

Предельный размер HTTP-ответа, включая заголовки и тело, — 65536 байт (64 КиБ).

Тайм-аут подключения и отдельных операций чтения и записи сокета — 4 секунды.

Для каждого HTTP-запроса создаётся отдельное TCP-соединение.

При превышении ограничения клиент завершает обработку с ошибкой и освобождает сокет.

Клиент использует заголовок Connection: close и получает данные до EOF. После получения ответа проверяются граница заголовков и соответствие размера тела значению Content-Length при наличии этого заголовка.

## 6. Закрытие соединения

При штатном завершении обмена TCP-соединение закрывается.

При получении EOF до завершения ожидаемого сообщения клиент сообщает об обрыве.

При недоступности сервера или разрыве соединения клиент сообщает об ошибке.

## 7. План проверок

1. Передача нескольких HTTP-запросов.
2. Получение сообщения несколькими операциями чтения.
3. Штатное закрытие соединения.
4. Закрытие клиента во время обмена.
5. Закрытие сервера во время обмена.
6. Обработка неполного сообщения.
7. Проверка ограничения размера ответа.

Ожидаемые результаты фиксируются до проведения экспериментов, фактические — после.
