## 1. Границы исследуемого участка

Исследуемый участок включает InMemoryBus, DeadbandFilter, StorageService, Database, REST API и лабораторный клиент межпроцессного обмена.

Основным внешним ресурсом модуля архивирования является база данных SQLite.

Для исследования IPC используется TCP-соединение между отдельным клиентским процессом и сервером FastAPI/Uvicorn.

## 3. Внутреннее состояние компонентов

InMemoryBus хранит текущие значения тегов и множество подписчиков.

Источник: src/core/bus.py:12–23.

DeadbandFilter хранит последние успешно зафиксированные значения и качество тегов.

Источник: src/core/deadband.py:16–39.

Эти структуры находятся в оперативной памяти процесса и не являются самостоятельными файловыми дескрипторами.

## 4. Владение и заимствование ресурсов

Объект Database отвечает за управление соединением SQLite.

Жизненным циклом Database управляет lifespan приложения: подключение выполняется перед запуском архивирования, закрытие — после завершения архивного обработчика.

StorageService и обработчики API используют Database без самостоятельного закрытия соединения.

StorageService получает очередь подписки от InMemoryBus и отвечает за своевременную отписку.

Клиентский сокет принадлежит функции request. Передача владения не производится.

## 5. Поведение при частичном отказе

В соответствии с CR-001 операция архивирования разделена на три этапа:

1. Проверка необходимости архивирования через would_store.
2. Сохранение значения через Database.save_tag.
3. Обновление состояния Deadband через mark_stored.

Источник: src/storage/service.py:25–33.

Если сохранение завершается исключением, третий этап не выполняется.

Ошибка журналируется, после чего StorageService продолжает обработку следующих элементов очереди.

Автоматическая повторная запись неудачного элемента не реализована. Последующее поступление значения может снова привести к попытке архивирования.

## 6. Тайм-ауты, повторные попытки и деградация

- TCP-клиент использует тайм-аут подключения и отдельных операций сокета 4 секунды.
- Получение истории повторяется до 15 раз при отсутствии записей с паузой 0,1 секунды.
- Автоматический повтор неудачной записи SQLite отсутствует.
- Для SQLite используется стандартный тайм-аут подключения библиотеки sqlite3; отдельное значение не задано.
- При ошибке архивирования обработчик продолжает работу, но не подтверждает сохранение неудачного значения.
- Текущие значения InMemoryBus могут оставаться доступными независимо от ошибки архивирования.
- При ошибке INSERT или commit выполняется попытка rollback.
- Отдельный тайм-аут завершения очереди архивирования отсутствует.

## 8. Ограничения исследования

В лабораторном режиме PollingEngine отключён. Команды управления ПЛК не отправляются.

Ресурсы Modbus и VirtualPLC не входят в исследуемый сценарий архивирования и лабораторного IPC.

Внутреннее управление серверными сокетами делегировано Uvicorn. Номера строк внутренней реализации библиотеки в настоящем документе не приводятся.
