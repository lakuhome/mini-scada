# ADR-002: Переход на React для конструктора мнемосхем и сборка через Docker

* **Статус:** Принято
* **Дата:** 8 октября 2026 г.
* **Авторы:** Котельников Павел, Марданов Андрей

---

## 1. Контекст

В рамках подготовки ко второй контрольной точке (КТ-2) разрабатывается интерактивный конструктор мнемосхем. Конструктор должен поддерживать:
1. Размещение на координатной сетке 14 типов промышленного оборудования по ГОСТ и ISA-5.1.
2. Перетаскивание элементов мышью (Drag & Drop) и привязку к тегам шины `InMemoryBus`.
3. Редактирование параметров через инспектор свойств и генерацию итогового файла конфигурации `config.json`.

Первоначальный стек предполагал использование чистого Vanilla JS / HTML5 (согласно ADR-001). Однако для интерактивного графического редактора со сложным состоянием (список виджетов, активный элемент, формы свойств, валидация порогов) ручное прямое манипулирование DOM-деревом приводит к высокой сложности синхронизации данных и интерфейса.

---

## 2. Принятое решение

1. **Использование React + Vite для веб-интерфейса:**
   * Интерфейс строится по компонентной модели: каждый примитив оборудования (насос, котёл, клапан, датчик) изолирован в отдельный переиспользуемый компонент.
   * Декларативное управление состоянием гарантирует согласованность данных схемы и визуального отображения.

2. **Изоляция исполнения:**
   * Веб-приложение исполняется в браузере клиента (в отдельном процессе V8) и физически не влияет на производительность Python Event Loop и сетевой опрос Modbus TCP.

3. **Сборка и воспроизводимость через многоэтапный Docker (Multi-stage build):**
   * Для соблюдения правила «легкий запуск из чистого клона» сборка фронтенда инкапсулируется внутри контейнера Docker.
   * На первом этапе (`node:20-alpine`) выполняется сборка (`npm run build`).
   * На втором этапе скомпилированные статические файлы передаются в контейнер Python 3.11, где раздаются через FastAPI.
   * Конечным пользователям и проверяющим не требуется устанавливать Node.js на хост-машину: вся система собирается и стартует одной командой `docker compose up --build`.

---

## 3. Последствия

### Положительные:
* Надежная компонентная архитектура для всех 14 промышленных примитивов.
* Отсутствие необходимости вручную синхронизировать DOM и массив конфигурации.
* Полная изоляция зависимостей Node.js внутри Docker-контейнера.

### Отрицательные и компенсационные меры:
* Появление шага сборки фронтенда в CI. Компенсируется добавлением стандартных шагов `actions/setup-node` в `.github/workflows/ci.yml`.
