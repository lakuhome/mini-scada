# ADR-003 — Согласованность SQLite и Deadband

## Статус

Принято в реализации ПР №3. Согласование CR-001 фиксируется отдельно.

## Контекст

StorageService использует DeadbandFilter для уменьшения количества записей исторических данных в SQLite.

Обновление состояния фильтра до подтверждения записи создаёт риск потери исторических значений при отказе базы данных.

## Рассмотренные варианты

1. Обновлять Deadband до записи и восстанавливать его состояние при ошибке.
2. Проверять Deadband без изменения состояния и обновлять его после успешного commit.

## Решение

Выбран второй вариант.

DeadbandFilter предоставляет методы would_store и mark_stored.

StorageService вызывает mark_stored только после успешного завершения Database.save_tag.

При исключении INSERT или commit Database предпринимает попытку отката транзакции.

## Обоснование

Двухфазный интерфейс не требует хранения дополнительной копии предыдущего состояния фильтра и исключает его преждевременное обновление при обычном исключении сохранения.

## Последствия

Положительные:

- отсутствие ложного подтверждения архивирования;
- возможность повторной обработки значения после ошибки;
- сохранение существующей модульной структуры;
- отсутствие необходимости передачи владения SQLite-соединением.

Ограничения:

- автоматическая повторная запись неудачного элемента отсутствует;
- отказ самого rollback требует отдельного рассмотрения;
- аварийное завершение процесса между commit и mark_stored не обеспечивает атомарности между SQLite и оперативной памятью.

## Проверка

Решение проверяется автоматизированными тестами StorageService и Database.
