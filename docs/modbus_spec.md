# Спецификация протокола Modbus TCP

Документ описывает бинарный формат сетевого обмена между нашим движком опроса (`Polling Engine`) и контроллером (`VirtualPLC`).

Связь работает по обычному TCP-сокету (по умолчанию порт `5020`). Все многобайтовые числа передаются в сетевом порядке байт — **Big-Endian** (в Python обозначается символом `>`).

---

## 1. Структура сетевого пакета (фрейма)

Любой пакет Modbus TCP (и запрос, и ответ) состоит из двух частей:
1. **Заголовок MBAP (7 байт)** — сетевой паспорт пакета.
2. **PDU (Protocol Data Unit)** — полезная нагрузка (номер команды и данные).

```text
┌───────────────────────────────┬───────────────────────────────┐
│     Заголовок MBAP (7 байт)   │          PDU (данные)         │
└───────────────────────────────┴───────────────────────────────┘
```

### Заголовок MBAP (7 байт)

| Поле | Размер | Формат `struct` | Значение | Описание |
|---|---|---|---|---|
| **Transaction ID** | 2 байта | `>H` | Счётчик запросов (1, 2, 3...) | Идентификатор пакета. Сервер возвращает тот же ID в ответе, чтобы клиент не перепутал ответы. |
| **Protocol ID** | 2 байта | `>H` | Всегда `0` | Признак протокола Modbus. |
| **Length** | 2 байта | `>H` | Число байт | Длина оставшейся части пакета (Unit ID + PDU). |
| **Unit ID** | 1 байт | `>B` | Обычно `1` | Адрес ведомого устройства на шине. |

## 2. Поддерживаемые команды (функции)

В рамках нашего MVP используются две базовые функции Modbus:

### Функция 03: Чтение регистров (Read Holding Registers)
Используется движком опроса для считывания показаний датчиков.

#### 1. Запрос от Polling Engine к ПЛК:
Клиент просит: «Начиная с регистра `0`, отдай мне `5` регистров подряд».
* **Код функции:** `0x03` (1 байт)
* **Начальный адрес:** `0x0000` (2 байта, `>H`)
* **Количество регистров:** `5` (2 байта, `>H`)

**Сборка запроса в Python:**
```python
# Заголовок (7 байт) + PDU (5 байт) = 12 байт
request = struct.pack(
    '>HHHBBHH',
    tx_id,          # Transaction ID
    0,              # Protocol ID (0)
    6,              # Length (Unit ID + 5 байт PDU = 6)
    1,              # Unit ID (1)
    3,              # Function Code (3)
    start_address,  # Начальный адрес регистра
    register_count  # Количество регистров
)
```

#### 2. Ответ от ПЛК к Polling Engine:
Контроллер возвращает сырые байты из своей памяти:
* **Код функции:** `0x03` (1 байт)
* **Количество байт данных:** `10` (1 байт, так как 5 регистров по 2 байта = 10 байт)
* **Значения регистров:** 10 байт сырых данных (5 чисел `uint16`).

**Распаковка ответа в Python:**
```python
# Сначала считываем ровно 7 байт заголовка:
mbap = await reader.readexactly(7)
tx_id, proto, length, unit_id = struct.unpack('>HHHB', mbap)

# Затем считываем ровно length - 1 байт полезной нагрузки:
pdu = await reader.readexactly(length - 1)
func_code = pdu[0]
byte_count = pdu[1]

# Распаковываем 16-битные регистры:
values = struct.unpack(f'>{byte_count // 2}H', pdu[2:])
# Результат: кортеж чисел, например (755, 210, 1, 0, 42)
```

### Функция 06: Запись одного регистра (Write Single Register)
Используется диспетчером для отправки команды на контроллер (включить насос, изменить целевую температуру).

* **Код функции:** `0x06` (1 байт)
* **Адрес регистра:** 2 байта (`>H`)
* **Новое значение:** 2 байта (`>H`)

**Ответ контроллера:**  
По стандарту Modbus при успешной записи сервер возвращает **точную копию (эхо) отправленного запроса**, подтверждая, что значение успешно сохранено в памяти.
