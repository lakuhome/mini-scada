# Границы проекта и сценарии развития (КТ-1 и КТ-2)

Документ определяет минимальный рабочий объем проекта на семестр, фиксирует результаты пройденных контрольных точек и регламентирует цели следующего этапа.

---

## 1. Сквозной сценарий движения данных

Цепочка движения данных от контроллера до рабочего места оператора:

1. **Генерация данных:** Симулятор ПЛК меняет значения в 16-битных регистрах (имитация температуры, давления, статуса насоса).
2. **Опрос по сети:** Модуль `PollingEngine` раз в секунду подключается по TCP (порт 5020) и запрашивает регистры функцией 03 Modbus TCP.
3. **Разбор пакета:** Полученные байты проверяются на корректность и преобразуются в числа Python.
4. **Обновление шины:** Значения упаковываются в структуры `Tag` со статусом `GOOD` (или `BAD` при сбое) и сохраняются в `InMemoryBus`.
5. **Фильтрация для архива:** `DeadbandFilter` сравнивает текущее значение с прошлым. Если разница превышает порог зоны нечувствительности, запись передается в асинхронное хранилище SQLite.
6. **Веб-трансляция:** Веб-сервер FastAPI транслирует актуальные срезы шины по WebSocket на клиентское приложение.
7. **Визуализация на мнемосхеме:** Веб-интерфейс на React сопоставляет теги со схемой, созданной в конструкторе, и динамически меняет цвета и показатели приборов.

## 2. Статус контрольных точек

### Контрольная точка 1 (КТ-1) — Завершена (тег `kt01-v1`)
* Эмулятор ПЛК (`VirtualPLC`) с функциями FC 03 и FC 06.
* Собственный движок опроса Modbus TCP на сокетах и модуле `struct`.
* Шина данных в памяти (`InMemoryBus`) со статусами качества (`GOOD`/`BAD`).
* Фильтр зоны нечувствительности (`DeadbandFilter`) и асинхронная база SQLite (режим WAL).
* Консольная точка входа `src/main.py` с автоматической самодиагностикой (`--check`) и режимом симуляции.

### Контрольная точка 2 (КТ-2) — Текущий этап разработки
* **Конструктор мнемосхем:** графический редактор на React с поддержкой 14 типов промышленного оборудования по ГОСТ/ISA-5.1 и экспортом/импортом файла `config.json`.
* **Веб-шлюз на FastAPI:** раздача статики интерфейса и высокоскоростной WebSocket-канал для передачи телеметрии.
* **Режим мониторинга (Run Time):** отображение живой мнемосхемы с индикацией состояний приборов (зеленый — норма, красный — авария/BAD).
* **Контейнеризация:** подготовка многоэтапного `Dockerfile` и `docker-compose.yml` для гарантированного запуска всей системы из чистого клона без локальной установки Node.js.

## 3. Резервный бэклог (отложено на финал)

* Подключение к физическому контроллеру через интерфейс RS-485/Ethernet.
* Интерактивные графики исторических трендов на основе данных SQLite.
* Авторизация пользователей и разделение прав доступа (оператор / инженер).
