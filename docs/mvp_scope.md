# Границы предварительного MVP и сквозной сценарий (КТ-1)

Документ фиксирует границы функциональности первой версии продукта, отделяя обязательное инженерное ядро от резервного бэклога.

---

## 1. Основной сквозной сценарий системы

```text
[Виртуальный ПЛК / Датчик]
           │ 
           │ 1. Изменение физических параметров (температура, давление)
           ▼
[Polling Engine (Опросчик)]
           │ 
           │ 2. Опрос регистров по Modbus TCP (FC 03) раз в 1 сек
           ▼
[In-Memory Bus (Шина данных)]
           │ 
           │ 3. Хранение тегов в RAM (id, value, quality, timestamp)
      ┌────┴────────────────────────┐
      ▼                             ▼
[Deadband Filter]           [FastAPI / WebSockets]
      │ 4. Фильтрация шума          │ 5. Мгновенная доставка в браузер
      ▼                             ▼
[SQLite3 WAL]               [Браузер оператора]
(запись при |Δ| >= 0.5)     (живое обновление без перезагрузки)
```

**Пошаговое описание сценария:**
1. Запускается виртуальный контроллер, генерирующий динамику технологического процесса (изменение температуры в регистре 0).
2. Движок опроса циклически подключается к ПЛК, формирует двоичный фрейм запроса Modbus TCP и парсит ответ.
3. Полученные значения преобразуются в структуры `Tag` и помещаются в `InMemoryBus`.
4. При сбое сети статус тега переключается на `BAD`, в шину попадает актуальная метка времени.
5. Фильтр `DeadbandFilter` сравнивает текущее значение с предыдущим записанным: если разница меньше пороговой, точка отбрасывается, иначе — асинхронно сбрасывается в SQLite.
6. Веб-интерфейс отображает актуальные значения датчиков и статус связи в браузере оператора в реальном времени.

## 2. Разделение функциональности

### Обязательное ядро (Must Have — требования к сдаче системы)
* [x] **Сетевой клиент Modbus TCP:** самописная реализация формирования MBAP + PDU для функции 03 (чтение) и функции 06 (запись) поверх `asyncio.StreamReader / StreamWriter` и `struct`.
* [x] **Эмулятор оборудования (Virtual PLC):** асинхронный сервер Modbus TCP с имитацией физического процесса для автономных тестов без контроллера.
* [x] **Шина данных в оперативной памяти (InMemoryBus):** быстрое thread-safe (в рамках Event Loop) хранилище тегов с поддержкой `publish` и `get`.
* [x] **Модель тега и статус достоверности:** поддержка флагов качества `GOOD` и `BAD`, отсечение `NaN`/`None`.
* [x] **Фильтр зоны нечувствительности (DeadbandFilter):** отсечение шума перед отправкой в архив для предотвращения деградации диска.
* [ ] **Асинхронный архив (SQLite WAL):** неблокирующая пакетная запись истории измерений в SQLite.
* [ ] **Веб-шлюз и веб-интерфейс:** эндпоинты FastAPI для отчетов и WebSocket-трансляция телеметрии на легковесный HTML/JS дашборд.

### Резервный список (Nice to Have — бэклог последующих этапов)
* [ ] Авторизация пользователей и разграничение прав доступа (роли «Наблюдатель» и «Инженер-наладчик»).
* [ ] Визуальный конструктор мнемосхем в браузере (drag-and-drop элементов).
* [ ] Опрос нескольких ПЛК по разным IP-адресам одновременно.
* [ ] Оповещения об авариях в Telegram / по email.
* [ ] Экспорт архивных журналов в форматы CSV/Excel/PDF.
* [ ] Переход с SQLite на распределенную Time-Series СУБД (TimescaleDB / InfluxDB).

## 3. Правило переноса функций

> **Регламентное правило:**  
> Перенос функций между Обязательным ядром и Резервом допускается только через явное решение команды с фиксацией в журнале архитектурных решений (ADR) или запросе на изменение (Change Request — CR). «Молчаливый сдвиг границ» из-за дефицита времени запрещен.
