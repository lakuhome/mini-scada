# Границы проекта и сценарий MVP (КТ-1)

Документ определяет минимальный рабочий объем проекта на семестр и разделяет функции на обязательные и резервные.

---

## 1. Сквозной сценарий работы

Цепочка движения данных от источника до экрана пользователя:

1. **Генерация данных:** Симулятор ПЛК меняет значения в 16-битных регистрах (имитация изменения температуры и давления).
2. **Опрос по сети:** Модуль `PollingEngine` раз в секунду подключается по TCP (порт 5020) и запрашивает регистры функцией 03 Modbus TCP.
3. **Разбор пакета:** Полученные байты проверяются на корректность и преобразуются в числа.
4. **Обновление шины:** Значения записываются в структуры `Tag` со статусом `GOOD` (или `BAD` при сбое) и попадают в `InMemoryBus`.
5. **Фильтрация для архива:** `DeadbandFilter` сравнивает текущее значение с прошлым сохраненным. Если разница больше порога, значение передается на запись в SQLite.
6. **Вывод на экран:** Веб-сервер транслирует изменения из шины по WebSocket на веб-страницу оператора.

---

## 2. Разделение функционала: Ядро и Резерв

### Обязательный результат на семестр (Ядро проекта)
* Симулятор ПЛК для локальной отладки (хранит регистры, имитирует изменения параметров).
* Движок опроса (Polling Engine) с чтением регистров (функция 03) и записью уставки (функция 06).
* Собственный разбор пакетов Modbus TCP на сокетах и модуле `struct`.
* Шина данных в памяти (`InMemoryBus`) для хранения актуальных тегов.
* Фильтр зоны нечувствительности (`DeadbandFilter`) для отсечения шума датчиков.
* Простая веб-панель в браузере для наблюдения за показаниями симулятора в реальном времени.
* Запись истории изменений в локальную базу данных SQLite.

### Резерв (отложено, если останется время)
* Переход на реальное физическое оборудование (подключение внешнего Modbus-датчика или контроллера).
* Веб-конфигуратор для переключения опроса с симулятора на внешние IP-адреса и настройки адресов регистров.
* Просмотр графиков истории за выбранный период времени.
* Разграничение прав пользователей (просмотр и управление).

## 3. Что пишем сами, а что берем готовым

### Пишем сами:
* Цикл опроса контроллера с обработкой разрывов соединения.
* Разбор, валидацию и упаковку Modbus TCP-пакетов (заголовок MBAP и PDU).
* Структуру тегов (`Tag`) и шину данных в оперативной памяти (`InMemoryBus`).
* Фильтрацию незначительных изменений (`DeadbandFilter`) и проверку допустимых диапазонов для уставок.
* Рассылку текущих значений по WebSocket и базовую веб-панель (HTML/JS).

### Берем готовым:
* `Python asyncio` — для асинхронной работы сети без блокировок.
* `struct` — стандартный модуль Python для упаковки чисел в бинарные строки.
* `FastAPI` и `Uvicorn` — для отдачи статических файлов и организации WebSocket-канала.
* `SQLite` — для локального файла базы данных.
* `pytest` — для модульного тестирования.

## 4. Результат на первую контрольную точку (КТ-1)
Работающее демо: два открытых терминала:
1. Симулятор ПЛК плавно меняет значения регистров на порту 5020.
2. Движок опроса каждую секунду считывает эти регистры и выводит их в консоль.
3. Единая точка запуска `python -m src.main --simulate` и процедура самодиагностики `python -m src.main --check`.
