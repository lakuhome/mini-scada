# Архитектура Edge-SCADA

Документ описывает внутреннее устройство, принципы взаимодействия модулей и потоки данных в системе.

---

## 1. Главный принцип: один асинхронный процесс (`asyncio`)

Вся система работает в **одном процессе Python на одном ядре процессора**, используя `asyncio` (Event Loop).

### Почему не потоки (`threading`) и не микросервисы?
1. **Минимум накладных расходов:** Переключение контекста между задачами в `asyncio` происходит почти мгновенно, без участия операционной системы.
2. **Простота отладки и запуска:** Проект не требует внешних брокеров сообщений (Redis, RabbitMQ, Kafka) и запускается в один клик.
3. **Безопасность памяти:** Нет race conditions между потоками на уровне памяти Python — состояние тегов хранится в оперативной памяти и мутируется предсказуемо.

### ⚠️ Критическое правило: запрет блокирующего I/O
Поскольку цикл событий один, любая синхронная дисковая операция (например, `sqlite3.connect()` или `time.sleep()`) замораживает **весь сервер целиком**:
* останавливается опрос контроллеров;
* зависают WebSocket-соединения у клиентов;
* копятся очереди сетевых пакетов.

**Все операции ввода-вывода (сеть, диск) обязаны быть асинхронными (`await`) либо выноситься в отдельный пул потоков (`asyncio.to_thread`).**

## 2. Разделение потоков данных (Быстрый и Архивный)

Чтобы частая запись на диск не тормозила живой интерфейс оператора, поток данных делится на два независимых маршрута:

```text
[ Контроллер ПЛК ]
        │ (Modbus TCP)
        ▼
[ Polling Engine (Опрос) ]
        │
        ▼
[ In-Memory Bus (Шина в памяти) ]
        ├───► [ WebSocket Сервер ] ───► [ Браузер оператора ]   (Быстрый поток)
        │
        └───► [ Deadband Фильтр ]  ───► [ База SQLite ]         (Архивный поток)
```

### 1. Быстрый поток (Живой экран оператора)
* **Цель:** Доставить свежие показания в браузер за минимальное время (миллисекунды).
* **Как работает:** Модуль веб-сокетов периодически считывает актуальные значения из `InMemoryBus` и транслирует их подключенным клиентам.
* **Особенность:** Никаких обращений к диску или базе данных. Только оперативная память и сетевые сокеты.

### 2. Архивный поток (История и аналитика)
* **Цель:** Сохранить историю изменения параметров для построения графиков и отчетов.
* **Как работает:**
  1. Значение из шины попадает в **`DeadbandFilter`** (фильтр зоны нечувствительности).
  2. Если показание изменилось незначительно (шум датчика в пределах порога), оно отбрасывается.
  3. Если показание изменилось существенно или изменился статус связи (`quality`), оно асинхронно записывается в SQLite.
* **Особенность:** Экономия дискового пространства до 90% и отсутствие нагрузки на диск при стабильных процессах.

## 3. Центральное звено: Шина данных в памяти (`InMemoryBus`)

**Шина данных (`src/core/bus.py`)** — это центральный диспетчер телеметрии в RAM.

### Зачем она нужна?
Вместо того чтобы модуль опроса напрямую вызывал сохранение в базу, отправку на веб-сокет и проверку аварий, он просто публикует данные в шину:
```python
bus.publish(tag)
```

А потребители (база данных, веб-сервер, алармы) берут данные из шины:
```python
tag = bus.get("Boiler_Temp_01")
all_tags = bus.get_all()
```

* **Полная изоляция:** Опросчик ничего не знает о веб-интерфейсе и базе данных. Если база данных временно недоступна, опрос датчиков продолжается без сбоев.
* **Скорость:** Чтение и запись в словарь Python занимают десятки наносекунд.

## 4. Зоны ответственности модулей

| Каталог | Назначение | Особенности |
|---|---|---|
| **`src/da/`** (Data Acquisition) | Движок опроса контроллеров по Modbus TCP | Открывает TCP-сокет, пакует и распаковывает бинарные фреймы (`struct`), обновляет теги в шине. |
| **`src/simulator/`** | Симулятор контроллера ПЛК | Запускает TCP-сервер на порту 5020, имитирует регистры Modbus и физические процессы (нагрев, синусоида, аварии). |
| **`src/core/`** | Модели данных и логика ядра | Описывает структуру `Tag`, шину `InMemoryBus`, фильтр шума `DeadbandFilter`. Без внешних зависимостей. |
| **`src/storage/`** | Сохранение истории | Асинхронная запись в SQLite (`tag_history`), управление индексами и режимом WAL. |
| **`src/api/`** | Веб-шлюз и REST API | FastAPI приложение: раздача статики, WebSocket-канал телеметрии, эндпоинты истории тегов. |
| **`src/tests/`** | Автоматические тесты | Тесты на pytest для проверки шины, фильтров, парсинга Modbus и базы данных. |
