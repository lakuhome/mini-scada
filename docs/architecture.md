# Архитектура mini-scada

Документ описывает внутреннее устройство системы, назначение модулей, движение данных и организацию веб-интерфейса.

---

## 1. Модель исполнения: один асинхронный процесс (`asyncio`)

Вся серверная часть системы работает в одном процессе Python с использованием библиотеки `asyncio`.

### Ключевые преимущества подхода:
1. **Простота развертывания:** системе не требуются сторонние очереди сообщений (Redis, RabbitMQ) или отдельные воркеры (Celery). Всё ядро стартует единым циклом событий.
2. **Эффективный сетевой ввод-вывод:** операции сетевого опроса по сокетам, а также удержание клиентских соединений WebSocket по своей природе являются операциями ожидания (I/O-bound). Цикл событий `asyncio` эффективно переключает контекст без блокировки процессора.
3. **Безопасность оперативной памяти:** код исполняется в одном системном потоке, благодаря чему чтение и запись тегов в словаре оперативной памяти происходят атомарно и не требуют тяжелых мьютексов.

### Неблокирующий Event Loop:
Любые долгие операции ввода-вывода (запись в базу данных на диск) выносятся в пул потоков через `asyncio.to_thread()`, а сетевые ожидания используют исключительно неблокирующий вызов `await asyncio.sleep()`.

## 2. Разделение потоков данных: Экран и Архив

Данные, поступающие из контроллера, разделяются на два независимых контура:

### Контур 1: Живой экран оператора (быстрый поток)
* **Назначение:** моментальное информирование диспетчера о текущих физических параметрах.
* **Механизм:** веб-сервер FastAPI опрашивает актуальный снимок `InMemoryBus` и отправляет его клиентам по протоколу WebSocket.
* **Особенность:** нулевое обращение к диску — данные передаются напрямую из оперативной памяти со скоростью сетевого стека.

### Контур 2: Архив технологической истории (архивный поток)
* **Назначение:** долговременное хранение изменений для отчетов и расследования инцидентов.
* **Механизм:**
  1. Тег из шины поступает в фильтр `DeadbandFilter`.
  2. Если амплитуда изменения значения датчика меньше установленного порога, точка признается технологическим шумом и отбрасывается.
  3. Если значение изменилось существенно или изменился статус качества связи (`GOOD` / `BAD`), запись передается в асинхронный сервис `StorageService` для вставки в SQLite.
* **Особенность:** защита диска от разрастания одинаковыми повторяющимися записями.

## 3. Организация веб-слоя и клиентского интерфейса

Клиентский интерфейс строится как одностраничное веб-приложение (Single Page Application) на React и функционирует в двух базовых режимах:

### Режим 1: Конструктор мнемосхем (Design Time)
* Позволяет оператору или инженеру в визуальном режиме собрать технологическую схему объекта.
* Включает каталог из 14 стандартных элементов оборудования по ГОСТ (котлы, баки, насосы, клапаны, датчики).
* Поддерживает свободное позиционирование элементов и привязку параметров оборудования к идентификаторам тегов шины данных.
* Результат конфигурации сохраняется в компактный файл `config.json`.

### Режим 2: Диспетчерский мониторинг (Run Time)
* Загружает файл `config.json` и отрисовывает технологическую схему на экране.
* Устанавливает постоянное WebSocket-соединение с сервером FastAPI.
* В реальном времени «оживляет» компоненты мнемосхемы:
  * Числовые значения и единицы измерения выводятся на цифровых шкалах;
  * Дискретные приборы (насосы, клапаны) меняют цветовую индикацию в соответствии со статусом;
  * При обрыве связи с контроллером приборы подсвечиваются статусом недостоверности (`BAD`).

## 4. Шина данных в памяти (`InMemoryBus`)

Шина данных (`src/core/bus.py`) служит центральным связующим звеном системы.

Опросчик контроллера полностью изолирован от веб-сервера и базы данных. Его единственная задача — получить данные из сети и выполнить:
```python
bus.publish(tag)
```

Веб-сервер и сервис архивации, в свою очередь, независимо читают состояние:
```python
tag = bus.get("Boiler_Temp_01")
```

Это гарантирует высокую надежность: сбой или медленная работа веб-клиента никак не нарушают непрерывность сбора данных с оборудования.

## 5. Структура каталогов проекта

* `src/simulator/` — эмулятор контроллера ПЛК (Modbus TCP сервер, симуляция физики процесса).
* `src/da/` (Data Acquisition) — движок опроса оборудования по протоколу Modbus TCP (функции FC 03, FC 06).
* `src/core/` — ядро системы (модель `Tag`, шина `InMemoryBus`, фильтр шума `DeadbandFilter`).
* `src/storage/` — асинхронное хранилище истории в базе данных SQLite (режим WAL).
* `src/api/` — веб-сервер на FastAPI (WebSocket-канал, REST API для истории и конфигураций).
* `frontend/` — клиентское веб-приложение на React (конструктор мнемосхем и живой мониторинг).
* `src/tests/` — набор автоматических тестов ядра на pytest.
