# Архитектура mini-scada

Документ описывает внутреннее устройство системы, назначение модулей и движение данных.

---

## 1. Модель исполнения: один асинхронный процесс (`asyncio`)

Вся система работает в одном процессе Python с использованием библиотеки `asyncio`.

### Почему выбран такой подход:
1. **Простота запуска:** проекту не нужны брокеры сообщений (Redis, RabbitMQ) или отдельные фоновые службы (Celery). Все запускается одной командой.
2. **Эффективность для сети:** операции опроса по сокетам и передача в WebSocket большую часть времени ждут ответа по сети (I/O-bound). В `asyncio` во время ожидания процессор переключается на другие задачи.
3. **Безопасность памяти:** код выполняется в одном потоке, поэтому при чтении и обновлении тегов в шине памяти нет риска гонок данных (race conditions) и не нужны сложные блокировки.

### Важное правило: не блокировать Event Loop
Так как цикл событий один, долгие синхронные операции (например, `time.sleep()` или синхронная запись на диск) заблокируют всю программу: перестанут опрашиваться датчики и зависнут веб-сокеты. Для ожидания используется `await asyncio.sleep()`, а запись в базу делается асинхронно.

## 2. Потоки данных: Экран и Архив

Данные из контроллера разделяются на два независимых пути:

### Путь 1: Живой экран в браузере (быстрый поток)
* **Цель:** передать свежие показания оператору без задержек.
* **Как работает:** веб-сервер считывает актуальные значения тегов из `InMemoryBus` и отправляет их в браузер по WebSocket.
* **Особенность:** здесь нет обращений к диску или базе данных, данные берутся прямо из оперативной памяти.

### Путь 2: История для графиков (архивный поток)
* **Цель:** сохранить историю изменений параметров, не раздувая файл базы данных.
* **Как работает:**
  1. Тег из шины передается в фильтр шума (`DeadbandFilter`).
  2. Если значение изменилось незначительно (в пределах погрешности датчика, например меньше 0.5 °C), оно отбрасывается.
  3. Если значение изменилось существенно или изменился статус связи (`quality`), точка сохраняется в SQLite.
* **Особенность:** база данных не забивается одинаковыми числами каждую секунду, экономя место на диске.

## 3. Шина данных в памяти (`InMemoryBus`)

Шина данных (`src/core/bus.py`) связывает компоненты между собой через обычный словарь Python в оперативной памяти.

### Зачем она нужна:
Опросчик контроллера ничего не знает про веб-интерфейс и базу данных. Он просто считывает регистры и публикует тег в шину:
```python
bus.publish(tag)
```

А веб-сервер и модуль записи в базу данных просто читают нужные теги из шины:
```python
tag = bus.get("Boiler_Temp_01")
```

Благодаря этому:
* Если временно недоступна база данных, опрос контроллера не прерывается.
* Если отвалился веб-клиент, это никак не влияет на сбор данных.
* Чтение и запись в словарь Python происходят мгновенно.

## 4. Назначение каталогов проекта

* **`src/simulator/`:** симулятор контроллера ПЛК. Держит массив регистров и плавно меняет значения для локальной отладки без физического оборудования.
* **`src/da/` (Data Acquisition):** движок опроса. Подключается по TCP-сокету, формирует и разбирает пакеты Modbus TCP, обновляет теги в шине.
* **`src/core/`:** ядро системы. Содержит структуру `Tag`, шину `InMemoryBus` и фильтр шума `DeadbandFilter`. Не зависит от сторонних библиотек.
* **`src/storage/`:** сохранение истории тегов в локальный файл базы данных SQLite.
* **`src/api/`:** веб-сервер на FastAPI для отдачи HTML-страницы и трансляции показаний по WebSocket.
* **`src/tests/`:** автоматические тесты на pytest для проверки шины, фильтра, разбора пакетов и самодиагностики.
