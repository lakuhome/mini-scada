# Техническая архитектура Edge-SCADA

Этот документ описывает внутреннее устройство, потоки данных и компоненты системы Edge-SCADA, спроектированной по принципу «System-First» с использованием чистого асинхронного Python (`asyncio`).

## 1. Разделение путей потока данных (Hot & Cold Path)

Для обеспечения высокой производительности и предотвращения блокировок ввода-вывода (I/O blocking), архитектура разделена на две независимые магистрали:

-   **Hot Path (Горячий путь):** 
    *   *Назначение:* Доставка телеметрии в реальном времени и отправка команд управления.
    *   *Компоненты:* Polling Engine (Layer 1) -> In-Memory Bus (Layer 2) -> WebSocket Gateway (Layer 4) -> Web UI (Layer 5).
    *   *Особенности:* Никаких блокирующих операций с диском или тяжелых вычислений. Только асинхронная работа в оперативной памяти и быстрая передача по сети.

-   **Cold Path (Холодный путь):**
    *   *Назначение:* Логирование, фильтрация шума, аналитика и долгосрочное хранение.
    *   *Компоненты:* In-Memory Bus (Layer 2) -> Deadband Filter -> SQLite Storage (Layer 3) -> REST API (Layer 4).
    *   *Особенности:* Асинхронные сбросы данных в базу, отсечение микроколебаний (Deadband) для экономии пространства и вычисление статусов качества (`GOOD`/`BAD`).

                                                                                 |
