# Контракт данных: Модель Тега (`Tag`)

Документ описывает базовую структуру данных системы — объект **`Tag`** (`src/core/models.py`). 

Это единый контракт данных, согласованный между разработчиками:
* **Модуль сбора данных (`src/da/`):** создает и обновляет теги при опросе контроллера.
* **Шина памяти (`src/core/bus.py`):** хранит теги в оперативной памяти.
* **Модуль хранения (`src/storage/`):** считывает теги и записывает их историю в SQLite.
* **Веб-интерфейс (`src/api/`):** отправляет поля тега клиентам по WebSocket и REST API.

---

## 1. Структура объекта `Tag`

```python
from dataclasses import dataclass, field
import time
from typing import Any

@dataclass
class Tag:
    id: str                                             # Уникальный строковый идентификатор
    value: Any = 0.0                                    # Актуальное значение (float, int, bool)
    timestamp: float = field(default_factory=time.time) # Unix-время обновления
    quality: str = "BAD"                                # Достоверность: "GOOD" или "BAD"
```

### Описание полей:

| Поле | Тип | Пример | Назначение |
|---|---|---|---|
| **`id`** | `str` | `"Boiler_Temp_01"` | Уникальное имя датчика/переменной в системе. По нему тег ищется в шине и базе. |
| **`value`** | `float`, `int`, `bool` | `75.5` | Текущее физическое значение (градусы, атмосферы, состояние реле). |
| **`timestamp`** | `float` | `1710000000.123` | Точное время последнего обновления (секунды с начала эпохи Unix). |
| **`quality`** | `str` | `"GOOD"` / `"BAD"` | Статус достоверности данных. Показывает, можно ли доверять показанию. |

---

## 2. Статусы качества (`quality`)

SCADA работает с реальным физическим миром, где датчик может перегореть, а кабель может быть перебит экскаватором. Отображать последнее значение «зависшим навсегда» смертельно опасно.

* **`"GOOD"`:** Связь с контроллером установлена, пакет успешно получен и распарсен, значение валидно.
* **`"BAD"`:** Кабель отключен, контроллер не ответил по таймауту, либо из сети пришел мусор (`None` / `NaN`).

### Методы изменения состояния:

1. **`tag.update_value(new_value)`:**
   Вызывается при получении свежих данных от контроллера.
   * Если пришло корректное число — обновляет `value`, ставит `quality = "GOOD"` и обновляет `timestamp`.
   * Если пришло `None` или `math.isnan(new_value)` — защищает систему от битых данных и переводит тег в `quality = "BAD"`.

2. **`tag.set_bad_quality()`:**
   Вызывается движком опроса, когда сокет с контроллером разорван или запрос завершился ошибкой таймаута. Значение остается прежним, но статус становится `"BAD"`. На экране оператора датчик подсветится серым/красным.

## 3. Пример использования

```python
from src.core.models import Tag

# Создание тега температуры котла
temp_tag = Tag(id="Boiler_Temp_01")

# Успешный опрос контроллера
temp_tag.update_value(78.4)
print(temp_tag.quality)  # "GOOD"

# Провод оборвался (таймаут сети)
temp_tag.set_bad_quality()
print(temp_tag.quality)  # "BAD"
```
