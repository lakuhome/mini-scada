# Правила разработки и инженерные стандарты проекта Edge-SCADA

Документ определяет стек, архитектурные границы и стандарты качества кода для разработчиков и ассистентов.

---

## 1. Цели и границы проекта

Edge-SCADA — легковесная система сбора данных и диспетчерского управления.
* **Главное правило разработки:** Проект строится итеративно, начиная с работающего минимального прототипа (MVP).
* **Ядро пишется вручную:** Логика протоколов, буферизация в памяти, фильтрация и обработка должны быть собственной понятной реализацией, а не компиляцией тяжелых сторонних комбайнов.

---

## 2. Стек технологий

* **Среда выполнения:** Python 3.11+ (чистый `asyncio`).
* **Протокол обмена с ПЛК:** Modbus TCP на сокетах (`asyncio.open_connection`, `struct`).
* **Веб-сервер / API:** FastAPI + WebSockets (для передачи телеметрии в реальном времени).
* **Хранилище:** SQLite3 в режиме WAL (для MVP) с последующим переходом на Time-Series DB при необходимости.
* **Фронтенд:** Vanilla JS / HTML5 + легкие графики (минимализм, без тяжелых фронтенд-сборок).
* **Инфраструктура:** Docker и Docker Compose для воспроизводимого запуска из чистого клона.

---

## 3. Архитектурные слои и границы

Проект разделен на изолированные модули с четкими границами. Модули общаются только через интерфейсы:

1. **Низкоуровневый ввод-вывод (`src/da/`):**
   * Движок опроса (`Polling Engine`).
   * Работает с TCP-сокетами, формирует бинарные пакеты (Big-Endian `>H`), читает и пишет регистры Modbus.
2. **Эмулятор оборудования (`src/simulator/`):**
   * Виртуальный ПЛК для локальной отладки и тестов без физического контроллера.
   * Умеет генерировать сбои: задержки, потерю пакетов, обрывы связи.
3. **Ядро и шина данных (`src/core/`):**
   * `InMemoryBus`: хранилище актуального состояния тегов в RAM.
   * `DeadbandFilter`: фильтрация шума и микроколебаний перед отправкой в архив.
4. **Слой хранения (`src/storage/`):**
   * Асинхронная запись истории тегов в базу данных без блокировки Event Loop.
   * Обязательное использование индексов и режима WAL в SQLite.
5. **Веб-шлюз (`src/api/` и `src/web/`):**
   * REST API для исторических данных.
   * WebSocket-сервер для мгновенной трансляции телеметрии клиентам.
   * Валидация диапазонов уставок перед отправкой команд на контроллер.

---

## 4. Инженерные стандарты и Code Review

Любой код (написанный разработчиком или сгенерированный ИИ) перед попаданием в `main` должен соответствовать критериям:

1. **Неблокирующий Event Loop:** Запрещено использовать синхронные блокирующие вызовы (`time.sleep()`, синхронный `sqlite3.connect()`, `requests`). Для I/O используются `await` или `asyncio.to_thread`.
2. **Тестируемость:** Критическая логика (парсинг Modbus, шина в памяти, фильтр шума, запись в БД) должна быть покрыта тестами на `pytest`.
3. **Отказоустойчивость:** Обрыв связи с контроллером, таймаут или битый пакет не должны приводить к падению сервера. Ошибка должна логироваться, теги переводятся в статус `"BAD"`, а движок опроса предпринимает попытки переподключения.
4. **Обоснованность:** Запрещено добавлять технологии (многопоточность, native-код, сторонние брокеры) без доказанной необходимости.
5. **Git Flow:** Разработка ведется по схеме `задача → ветка → PR → code review → merge`.
