# Project Context: Edge-SCADA (Web-Oriented Telemetry & Control)

## 1. Vision & Scope
Легковесная веб-ориентированная система сбора данных и диспетчерского управления (SCADA). 
Проект реализует полный цикл работы с данными: от низкоуровневого сетевого взаимодействия с аппаратными контроллерами до визуализации в реальном времени.
**Критическое правило:** разработка ведется итеративно, начиная с небольшого работающего MVP, где ядром является собственная программная логика, а не сборка из готовых админок[cite: 1].

## 2. Tech Stack & Environment
- **Runtime:** Python 3.11+ (Asyncio-first).
- **Hardware/Network Protocol:** Modbus TCP (`pymodbus`) / Raw TCP Sockets.
- **Backend/API:** FastAPI + WebSockets (Real-time data push).
- **Storage:** SQLite3 (MVP) -> Time-Series DB (целевая среда).
- **Frontend:** Vanilla JS / HTML5 + Chart.js (минимализм, отсутствие тяжелых сборок).
- **Infrastructure:** Docker, Docker Compose для обеспечения воспроизводимой сборки и запуска из чистого клона[cite: 1].

## 3. System Architecture (Layered Design)
Проект разделен на изолированные домены (модули) с четкими границами и контрактами[cite: 1]. Пересечение границ допускается только через определенные интерфейсы (API/Queues).

### Layer 1: Hardware I/O & Network (Низкоуровневый слой)
- **`src/da/` (Data Acquisition):** Движок опроса (Polling Engine). Отвечает за открытие сокетов, формирование бинарных пакетов, обработку Endianness и чтение/запись регистров контроллеров. 
- **`src/simulator/`:** Изолированный виртуальный ПЛК (PLC Emulator). Генерирует физические процессы и используется для инструментальной диагностики сбоев (потери пакетов, таймауты)[cite: 1].

### Layer 2: Core Processing & In-Memory Bus (Ядро и память)
- **`src/core/`:** Программная шина данных. Хранит актуальное состояние (state) всех тегов в оперативной памяти. Осуществляет фильтрацию шума (Deadband), расчет производных значений и управляет аллокацией памяти, чтобы избежать утечек.

### Layer 3: Storage & Persistence (Хранение)
- **`src/storage/`:** Асинхронная запись истории изменения тегов и журнала событий на диск (базу данных). Должна работать без блокировки основного Event Loop.

### Layer 4: Real-time Gateway & Security (Шлюз и безопасность)
- **`src/api/`:** REST API для исторических данных и WebSocket-сервер для мгновенной потоковой передачи телеметрии клиентам.
- **`src/security/`:** Реализация минимальной модели угроз[cite: 1]. Модуль инспекции команд: валидация уставок на запись (Safety Limits), проверка прав доступа (Role-Based Access) перед отправкой управляющей команды на Layer 1[cite: 1].

### Layer 5: Web UI (Представление)
- **`src/web/`:** Клиентская часть. Панель мониторинга, подписка на WebSocket, рендер графиков и обработка аварий (Alarms).

## 4. Quality & Engineering Standards
Любой код, попадающий в кодовую базу (в том числе сгенерированный ИИ), является зоной ответственности команды и должен удовлетворять следующим требованиям[cite: 1]:

1. **Измеримость:** Ключевые узлы (Polling Engine, WebSocket Gateway) должны поддаваться профилированию. Разработчик должен иметь возможность измерить хотя бы одно свойство: потребление памяти, процессорное время, задержку (latency) или пропускную способность[cite: 1].
2. **Тестируемость:** Наличие тестов и автоматической проверки хотя бы для критической логики ядра (валидация данных, обработка обрывов связи)[cite: 1].
3. **Отказоустойчивость:** Ни один отвал сети или некорректный пакет от датчика не должен приводить к падению (Crash) всего сервера. Система должна логировать дефект и восстанавливать работу.
4. **Обоснованность:** Запрещено добавлять технологии (многопоточность, native-код, сторонние брокеры) «ради галочки» без доказанной инженерной необходимости[cite: 1].

## 5. Workflow & Git Flow
- Нормальный цикл разработки: `задача → ветка → изменение → проверка (тесты/линтеры) → review → merge` в основную ветку[cite: 1].
- Обязательно использование семантических коммитов. Ключевые этапы (MVP, Release Candidate) фиксируются через `git tag`[cite: 1].
- Проект должен содержать `README.md` с понятной инструкцией по запуску подготовленной целевой среды и пакета поставки[cite: 1].
