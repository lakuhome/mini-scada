# mini-scada

Легковесная веб-ориентированная система для опроса аппаратных контроллеров по сети и визуализации телеметрии в реальном времени.

Проект связывает контроллер (виртуальный симулятор или реальный ПЛК) с браузером: опрашивает регистры по протоколу Modbus TCP, раскладывает полученные байты по тегам в оперативной памяти, отсеивает мелкий шум датчиков и транслирует свежие значения на веб-панель.

> **Текущий этап:** Контрольная точка 1 (КТ-1).  
> **Фиксированный тег репозитория:** `kt01-v1`

### Для кого продукт и какую задачу решает
* **Кейс 1 (учебный и исследовательский):** студент или начинающий инженер, который изучает промышленную автоматизацию. Ему нужно на практике понять, как сырые байты из регистров контроллера доходят до веб-интерфейса. Тяжелые закрытые коммерческие SCADA прячут всю внутреннюю кухню и требуют дорогого оборудования. Наш проект открытый, простой и разделен на понятные слои, где виден путь каждого байта.
* **Кейс 2 (прикладной):** энтузиаст или специалист малой автоматизации, которому нужно контролировать локальный процесс (климат в теплице, домашнюю котельную, насос). Ему нужен простой инструмент сбора данных без лишних затрат и сложной настройки.

### Как задача решается сейчас
* В обучении: работа с симуляторами закрытых проприетарных систем или чисто теоретическое изучение протоколов по учебникам.
* На практике: ручной контроль показаний на месте либо покупка тяжелых SCADA-пакетов, избыточных для пары датчиков.

### Основной сценарий работы
1. Пользователь запускает симулятор ПЛК (или подключает реальный контроллер к сети).
2. Система раз в секунду опрашивает контроллер: формирует запрос Modbus TCP (функция 03), считывает регистры, проверяет целостность пакета.
3. Полученные числа упаковываются в объекты тегов (значение, время, статус качества `GOOD` или `BAD`) и сохраняются в шину памяти.
4. Значения передаются в браузер по WebSocket, и пользователь видит текущие показатели на экране.
5. Фильтр зоны нечувствительности отсекает мелкие колебания датчиков и отправляет в базу SQLite только значимые изменения.
6. При отправке команды управления (функция 06) значение проверяется на допустимый диапазон и записывается в регистр контроллера.

### Что пишем сами, а что берем готовым

**Пишем сами:**
* Цикл опроса контроллера с повторным подключением при сбоях.
* Разбор и проверку сетевых пакетов Modbus TCP (функции 03 и 06).
* Структуру тегов (`Tag`) и шину данных в памяти (`InMemoryBus`).
* Фильтрацию шума датчиков (`DeadbandFilter`) перед записью в базу.
* Проверку диапазонов уставок перед записью в регистры.
* Рассылку данных клиентам и простую веб-панель.

**Берем готовым:**
* Стандартную библиотеку Python (`asyncio` для асинхронного цикла событий, `struct` для упаковки байт).
* `FastAPI` и `Uvicorn` для веб-сервера и раздачи статики.
* Протокол WebSocket для передачи данных в браузер.
* Базу данных SQLite для локального хранения истории.
* `pytest` для автоматических тестов.

### Модуль для отдельного наблюдения и экспериментов
* **`DeadbandFilter` (фильтр шума):** можно подавать искусственный поток чисел с разной амплитудой шума и измерять, сколько записей отсеивается и сколько ресурсов процессора на это уходит.
* **`PollingEngine` (движок опроса):** можно замерять время ответа контроллера и стабильность чтения при разной частоте опроса.

### Внешние ресурсы
* Сеть: TCP-сокеты Modbus TCP (порт 5020) и соединение WebSocket с браузером.
* Локальный диск: файл базы данных SQLite.

## 2. Как устроена система

Система работает в одном асинхронном процессе Python и состоит из простых шагов:

1. **Симулятор ПЛК (`src/simulator/`):** имитирует поведение контроллера. Слушает TCP-порт 5020, держит в памяти массив 16-битных регистров и плавно меняет показания (температуру, давление).
2. **Движок опроса (`src/da/`):** регулярно отправляет запрос чтения Modbus TCP, забирает сырые байты, проверяет их и преобразует в понятные теги.
3. **Шина данных в памяти (`src/core/bus.py`):** общий словарь в RAM. Опросчик складывает туда свежие теги, а веб-сервер и модуль архива забирают их без взаимных блокировок.
4. **Фильтр шума (`src/core/deadband.py`):** сравнивает свежее значение с предыдущим. Если датчик изменился меньше чем на заданный порог (например, меньше 0.5 °C), запись в архив не идет. Это защищает базу от переполнения одинаковыми цифрами.
5. **Веб-часть (`src/api/`):** отдает страницу в браузер и транслирует изменения тегов по WebSocket.

## 3. Границы проекта на семестр

* **Обязательный результат (MVP):** работающий симулятор ПЛК, стабильный опрос по Modbus TCP, шина данных в памяти, фильтрация шума, простая веб-панель в браузере с отображением живых значений.
* **Резерв (если останется время):** подключение к реальному физическому контроллеру, конфигуратор для переключения между симулятором и внешним железом, базовые графики истории.

## 4. Быстрый запуск

### Подготовка окружения
Нужен Python 3.11+.

```bash
# Клонируем репозиторий
git clone https://github.com/lakuhome/mini-scada.git
cd mini-scada

# Создаем и активируем виртуальное окружение
python -m venv venv

# Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# Linux / macOS:
source venv/bin/activate

# Ставим зависимости
pip install -r requirements.txt
```

### Демонстрация к первой практической (КТ-1)

**Вариант 1. Запуск в два терминала (как заявлено в плане):**
* В первом терминале запускаем симулятор ПЛК:
  ```bash
  python -m src.simulator.virtual_plc
  ```
* Во втором терминале запускаем опросчик:
  ```bash
  python -m src.da.polling_engine
  ```
  Опросчик подключится к симулятору, начнет считывать регистры раз в секунду и выводить их значения в консоль.

**Вариант 2. Запуск сквозного демо одной командой:**
```bash
python -m src.main --simulate
```
Запускает симулятор, опрос, шину данных и фильтр шума в одном окне.

**Проверка самодиагностики (Healthcheck):**
```bash
python -m src.main --check
```
Проверяет шину, логику фильтра и разбор пакетов Modbus. Выводит статус `OK` и возвращает код 0.

### Запуск тестов
```bash
pytest -v
```
