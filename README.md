# mini-scada

Учебная система сбора данных и управления котельной: собственный Modbus TCP,
асинхронный Python, SQLite WAL, FastAPI и страница оператора на React + Vite.

## Запуск MVP

Нужен запущенный Docker Engine / Docker Desktop с Linux-контейнерами.

```powershell
docker compose up --build
```

Открыть [страницу оператора](http://127.0.0.1:8000).
Compose запускает виртуальный ПЛК и приложение. На странице видны температура,
давление, насос, авария, состояние связи и текущая уставка. Температура симулятора
постепенно приближается к заданной уставке. Для демо разрешена запись только
регистра 4: от 20.0 до 100.0 °C.

История хранится в Docker volume `history` и сохраняется после `docker compose down`.
`docker compose down --volumes` удаляет историю. Конструктор мнемосхем в MVP не входит.
Авторизации нет: порт опубликован только на localhost, стенд рассчитан на локальную работу.

## Локальная разработка без Docker

Python 3.11+, Node.js 24, npm. Из корня проекта:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Сборка страницы (из корня):

```powershell
npm --prefix frontend ci
npm --prefix frontend run build
```

Первый терминал, с активированным окружением:

```powershell
python -m src.simulator.virtual_plc
```

Второй терминал, с активированным окружением (PowerShell):

```powershell
$env:SCADA_SAFETY_LIMITS = '{"4":[200,1000]}'
python -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Для разработки с автоматическим обновлением интерфейса
можно дополнительно выполнить `npm --prefix frontend run dev`: Vite проксирует
`/api` и `/ws` на локальный сервер :8000. После изменения сборки перезапустить Uvicorn,
если каталог `frontend/dist` отсутствовал при старте.

## Что происходит с данными

1. ПЛК хранит uint16-регистры. Опросчик читает FC03, проверяет ответ и публикует `Tag` в шину.
2. Шина хранит копии последних состояний. Теги до первого чтения и при сбое имеют качество `BAD`.
3. Архиватор получает события через очередь, фильтрует мелкие изменения и пишет в SQLite.
4. WebSocket отправляет полный снимок шины каждые 0.5 секунды. Медленный клиент не тормозит опрос.
5. React показывает значения в физических единицах, состояние связи и историю.
6. Сервер проверяет уставку, отправляет FC06. Интерфейс отдельно ждёт подтверждения очередным FC03.

В шине, REST API, WebSocket и базе значения **сырые**. `/api/catalog` задаёт единицы
и `divisor`: температура /10, давление /100. Например, `750` → 75.0 °C.
Архивный deadband 1.0 применяется к сырым значениям: 0.1 °C или 0.01 бар.
Смена качества сохраняется независимо от deadband. В архиве `BAD` с числом 0 не
означает реальное нулевое измерение; интерфейс скрывает недостоверные значения.

## Настройка сервера

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SCADA_PLC_HOST` | `127.0.0.1` | Адрес ПЛК |
| `SCADA_PLC_PORT` | `5020` | Порт Modbus TCP |
| `SCADA_POLL_INTERVAL` | `1.0` | Пауза между опросами, секунды |
| `SCADA_DB_PATH` | `scada.db` | Файл истории |
| `SCADA_SAFETY_LIMITS` | `{}` | JSON: адрес → [минимум, максимум] в сырых единицах |
| `SCADA_WEB_DIR` | `frontend/dist` от корня проекта | Собранная страница |

Переменные читаются при запуске. Без `SCADA_SAFETY_LIMITS` запись запрещена.
Параметры веб-страницы не могут расширять серверные разрешения. Настройки демо
не являются настройками для реального оборудования.

| Интерфейс | Назначение |
|---|---|
| `GET /api/health` | Доступность API; не проверяет связь с ПЛК |
| `GET /api/catalog` | Метаданные и разрешённые пределы записи |
| `GET /api/tags` | Актуальные теги |
| `GET /api/tags/{id}` | Один тег |
| `GET /api/tags/{id}/history?limit=100&start=...&end=...` | История, новые записи первыми |
| `POST /api/tags/{id}/setpoint` | `{ "value": 82.5 }` в физических единицах |
| `POST /api/commands/write-register` | `{ "register": 4, "value": 825 }` в сырых единицах |
| `WS /ws/tags` | `{ "type": "snapshot", "server_time": ..., "tags": [...] }` |
| `/docs` | Интерактивная документация REST API |

Время — Unix timestamp, границы истории включительны, `limit` от 1 до 1000.
Выход за диапазон или неточное представление уставки возвращает 422, ошибка ПЛК — 502.
Успешный ответ команды содержит `acknowledged_at`: для подтверждения интерфейс
ожидает измерение с более поздним серверным временем и целевым значением.

## Демонстрация отказов

При работающем Compose:

```powershell
docker compose stop plc
docker compose start plc
```

После отключения панель показывает `BAD`, после восстановления возвращает живые
значения без перезапуска приложения. Потеря WebSocket отображается отдельно;
страница автоматически переподключается. Последние значения не выдаются за актуальные.

Для задержек и обрывов при локальной разработке:

```powershell
python -m src.simulator.virtual_plc --response-delay 5
python -m src.simulator.virtual_plc --disconnect-every 4
```

Команды запускаются по отдельности вместо обычного симулятора. Таймаут опросчика — 3 секунды.

## Консольное демо и тесты

Старое консольное демо сохраняется:

```powershell
python -m src.main
python -m src.main --mode simulate --interval 1 --threshold 0.5
python -m src.main --mode plc
python -m src.main --mode poll
python -m src.main --check
```

`src.main` демонстрирует ПЛК, опрос, шину и фильтр в консоли; надпись `[ARCHIVE]`
показывает решение фильтра. Для настоящего архива и страницы запускайте API или Compose.
Флага `--simulate` нет, используется `--mode simulate` или режим по умолчанию.

```powershell
python -m pytest -q
npm --prefix frontend run lint
npm --prefix frontend test
npm --prefix frontend run build
```

Браузерные тесты поднимают отдельные ПЛК (:15020) и API (:18000) с тестовой базой:

```powershell
# Из frontend, с активированным Python-окружением:
npx playwright install chromium
npm run test:e2e
```

Проверяются живые значения, подтверждённая уставка, архив, переподключение и мобильная
ширина страницы. Python-тесты проверяют протокол, BAD/GOOD, таймауты, архив и восстановление TCP.
