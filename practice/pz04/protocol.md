# Протокол практической работы № 4

База — `2a3a260`, версия DeadbandFilter и StorageService после CR-001. Модуль-кандидат и параметр взяты из отчёта Марданова Андрея Сергеевича по ПР № 2. Все экспериментальные версии находятся в этом каталоге.

Запуск из корня репозитория: `python -m practice.pz04.experiment`. Python работает без отладчика. Источники входа детерминированы формулами, генератор случайных чисел не используется. Для каждого варианта предусмотрены два прогрева и пять повторов. Варианты чередуются внутри каждого круга. Измеряется время по `perf_counter`, прогревы хранятся отдельно. Сравниваются минимум, медиана, максимум и относительный размах `(max − min) / median`. Выбросы сохраняются. Перекрывающиеся диапазоны без разницы медиан заметно больше разброса дают вывод «различие не установлено».

## Ожидания до измерений

| Результат | Вход, способ измерения и прогноз |
|---|---|
| Р1–Р2 | 96 независимых историй по 8000 значений. Один процесс обрабатывает историю последовательно, результаты объединяются в исходном порядке. Таймер включает передачу данных, запуск и остановку пула. При условной доле последовательной работы 10% модель Амдала даёт S(2)=1,82, S(4)=3,08, S(12)=5,71. Это ориентир без учёта накладных расходов. Для одного процесса пула ожидается S ниже 1 из-за передачи входа и запуска. |
| Р3 | По 48 запросов к временной SQLite, каждый читает 256 строк соответствующего тега. Запросы используют тот же метод чтения, что Database. Сравнение последовательного выполнения и 2, 4, 8 одновременных задач на отдельных соединениях. Кэш файловой системы тёплый после подготовки БД и прогревов, очистка не выполняется. Если операции только ждут независимый ресурс, идеальная граница составит T/p. Здесь запросы короткие, поэтому накладные расходы соединений и конкуренция за выполнение Python могут устранить выигрыш. |
| Р4 | Инвариант модели состояния архивирования: одному ключу перехода соответствует ровно одно принятие. Барьер после чтения состояния вынуждает обоих исполнителей увидеть отсутствующий ключ. Ожидается 100 нарушений на 100 попыток, под блокировкой и с повторной проверкой — 0. Измеряется стоимость полного сценария, включая барьер, планирование и повторную проверку. |
| Р5–Р6 | Вход ПР № 2: TEMP_01 со значениями 20,0 → 20,2 → 20,5 при пороге 0,5. Для измерения исходная тройка повторяется 60 раз, качество GOOD. Порог 0,5 должен принять 120 записей, порог 0,75 — одну. Гипотеза: число записей уменьшится на 99,17%, а медиана времени архивирования — не менее чем вдвое за счёт сокращения числа транзакций. Любое расхождение счёта либо снижение времени меньше чем вдвое опровергает соответствующую часть прогноза. Измеряется цикл StorageService; создание временной базы, открытие, проверка истории и закрытие вне таймера. |
