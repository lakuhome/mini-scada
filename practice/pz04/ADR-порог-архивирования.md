# Порог фильтра архивирования

Автор индивидуальной работы — Марданов Андрей Сергеевич. Статус вердикта — предложен к проверке.

## Контекст

Модуль-кандидат DeadbandFilter. В профиле ПР № 2 исследуется влияние порога на число записей SQLite. CR-001 обновляет базовую точку после записи, поэтому число принятых значений проверяется по истории базы.

## Варианты и данные

Базовый порог 0,5 и альтернативный порог 0,75. До запусков записан прогноз о 120 и одной записи на 180 значений и уменьшении медианы времени не менее чем вдвое. Число записей изменилось с 120 до 1 (99.17% сокращения). Отношение медиан составило 73.84. Порог 0,75: второй вариант быстрее, диапазоны не перекрываются. Прогноз по числу записей подтверждён. Отношение медиан достигло прогнозного значения.

## Вердикт и проверка

Ограничить применение порога 0,75 потоками, для которых можно пропускать изменения в пределах 0,75 единицы. На исследованном входе при пороге 0,75 значение 20,5 не попадает в историю. Порог продукта сохраняется. Цена повышения порога — потеря детализации. Границы вывода: один тег TEMP_01 качества GOOD, периодическая тройка из ПР №2, 180 значений, свежая SQLite WAL на каждом прогоне и локальный Windows на Core i5-1235U. Проверка выполняется тестами Deadband и сравнением числа строк истории в учебном сценарии.
